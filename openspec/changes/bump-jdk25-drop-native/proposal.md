## Why

The `project-scaffolding` change made a **GraalVM native image** the API's
production target (ADR-13), chosen for its memory footprint (~50–150MB RSS vs.
300–500MB on the JVM) on a shared 4GB VPS. Bringing that toolchain up to
GraalVM 25 (the unmerged work on this branch) made the ongoing *cost* of the
native path concrete:

- **A hand-maintained reachability-metadata burden.** Reflection/resource
  metadata is regenerated by a tracing agent, but the AWT/Java2D **JNI** block
  is not agent-derivable and is hand-maintained — a crash the resize path hit at
  `Toolkit.loadLibraries`. Every new dependency or reflection path risks
  native-only breakage that does not show up on the JVM.
- **A ~5-minute native build + smoke test on every push.** The GraalVM
  `nativeCompile` dominates CI wall-clock, slowing the feedback loop on changes
  that have nothing to do with native.
- **Library constraints** (ADR-13 consequences) that must be honoured purely to
  stay native-compatible.

At POC scale, that friction outweighs the memory saving — and plain JVM with a
tuned small heap is the alternative ADR-13 itself named. The JDK-25 toolchain
cascade on this branch is **pure upside on the JVM**, so we keep it and drop
only the native image. This revisits **ADR-13**.

## What Changes

- **Keep** the JDK-25 toolchain bump landed on this branch: `jvmToolchain(25)`,
  Gradle 9.7.1, Kotlin 2.2.21, Ktor 3.5.2, `eclipse-temurin:25-*` for the JVM
  image. None of it is native-specific; all of it runs on a plain JVM.
- **Drop the GraalVM native production target:**
  - Delete `api/Dockerfile.native`.
  - Remove the `graalvmNative { }` block and the `graalvm.native` plugin from
    `api/app/build.gradle.kts`, and the `native-build-tools` version +
    `graalvm-native` plugin entry from the version catalog.
  - `git rm` the reachability metadata under
    `api/app/src/main/resources/META-INF/native-image/com.rewear/**` (both the
    agent-owned `app/` file and the hand-maintained `awt/` JNI net).
- **Promote the JVM image to production:** rename `api/Dockerfile.jvm` →
  `api/Dockerfile`, add a heap cap (`-XX:MaxRAMPercentage=75`) so it behaves on
  the 4GB VPS. One image serves dev and prod (better parity).
- **Drop the native-only Flyway workaround:** native images cannot scan
  classpath migration directories, so migrations were baked to the filesystem via
  `MIGRATIONS_LOCATION_PREFIX`. On the JVM, `Migrations.kt` already defaults to
  `classpath:db/migration`, so the production image stops setting that env var
  (the code seam stays — it is env-driven per ADR-9).
- **CI (`.github/workflows/ci.yml`):** remove the native build step; repoint the
  smoke test at the JVM image; publish a single `rewear-api` image (`sha-<short>`
  + `latest`). Removes the ~5-min native build from every push.
- **Docs:** revisit **ADR-13** (native → superseded, with the reversal
  rationale), touch **ADR-10** (`rewear-api` is a JVM image, not a native
  binary), and update `README.md` + `docs/ROADMAP.md`.

No product/domain behaviour changes; no runtime API changes. R2DBC is retained
(see design — the native-metadata rationale for the JDBC fallback is now void,
but R2DBC runs fine on the JVM; switching persistence is out of scope).

### Modified Capabilities

- **`build-and-release-pipeline`** — the production target changes from a GraalVM
  native image to a single JVM image. The "dual image build" and "native image
  smoke test" requirements are removed; a "single JVM production image" and a
  JVM-image smoke test replace them, and the publish requirement drops to one
  image. See `specs/build-and-release-pipeline/spec.md`.

## Impact

- **Build/config**: `api/app/build.gradle.kts` (remove `graalvmNative` + plugin),
  `api/gradle/libs.versions.toml` (remove `native-build-tools` + `graalvm-native`).
  `api/buildSrc/src/main/kotlin/rewear.kotlin-common.gradle.kts` is unchanged
  (JDK-25 toolchain / JVM-24 target stay).
- **Images**: delete `api/Dockerfile.native`; rename `api/Dockerfile.jvm` →
  `api/Dockerfile` and add the heap cap.
- **Metadata**: `git rm` `api/app/src/main/resources/META-INF/native-image/**`.
- **Migrations**: `api/app/.../Migrations.kt` seam unchanged; the production
  image stops setting `MIGRATIONS_LOCATION_PREFIX` and drops the `COPY …/migrations`
  lines.
- **CI**: `.github/workflows/ci.yml` — drop native build/smoke; single-image
  build, JVM smoke test, single-image publish.
- **Docs**: `docs/ARCHITECTURE.md` (ADR-13, ADR-10), `README.md`, `docs/ROADMAP.md`.
- **Verification**: `./gradlew build` passes on JDK 25; the JVM image boots,
  `/health` returns the git SHA, migrations apply, and `/internal/resize-check`
  succeeds.
- **Risk**: higher memory footprint on the VPS (~300–500MB vs. ~50–150MB) — an
  accepted trade at POC scale with a named trigger to revisit (see design).
  Rollback is a revert of this change's commit.
